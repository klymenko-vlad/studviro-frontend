## Version-specific gotchas in this repo

- Middleware is `src/proxy.ts`, not `middleware.ts`.
- Turbopack is the default for `dev` and `build`; there is no webpack config.
- `params` and `searchParams` are Promises — `await` them.
- The locale comes from the `NEXT_LOCALE` cookie, read in
  `shared/config/i18n/request.ts`. There is no `[locale]` segment and no
  `setRequestLocale` — see [ADR 0007](docs/adr/0007-locale-in-cookie.md).
- Dev server is port **3001** (the backend owns 3000).

## Hard rules

1. **Layers depend downward only**: `app → views → widgets → features → entities → shared`.
   Never sideways, never upward. Enforced by `eslint-plugin-boundaries`.
2. **Import slices through their `index.ts`.** No deep imports, no `../../` climbing.
3. **Never edit `src/shared/api/generated/`** and never import from it directly —
   go through `@/shared/api`. It is regenerated by `pnpm api:generate` and diffed in CI.
4. **No hard-coded user-facing strings.** Add a key to `messages/en.json` _and_
   `messages/uk.json`. Unknown keys are a type error.
5. **shadcn/ui is the only UI kit.** Never hand-roll a primitive it already
   ships, and never import a Radix package directly in a feature. See
   [UI conventions](#ui-conventions).
6. **Semantic design tokens only** — `bg-card`, `text-destructive`. Never raw
   palette values (`bg-blue-500`, `#1e293b`, `text-slate-400`) outside
   `src/app/globals.css`, and never a colour that has no dark-mode counterpart.
7. **Server Components by default.** Add `'use client'` to the smallest interactive
   leaf, not to a page or layout.
8. **Navigate with `Link`/`useRouter` from `@/shared/config`.** They are the
   plain Next primitives today, but the barrel is the seam — importing
   `next/link` directly means the next routing change has to touch every file.
9. **No `console`.** Use `logger` from `@/shared/lib` — it fans out to registered
   sinks; `console` reaches no APM. Enforced by `no-console`.
10. **Inline `<script>` needs the nonce.** The CSP in `src/proxy.ts` mints one
    per request and passes it on the `x-nonce` request header; a tag without it
    is blocked. Never add a hash to `script-src` — it makes browsers ignore the
    nonce and stops the page hydrating. See
    [ADR 0009](docs/adr/0009-nonce-based-csp.md). Prefer an external module.
11. **Tokens never reach the browser.** `/api/auth/*` and `shared/auth/` are the
    only modules that touch one; everything client-side goes through the
    same-origin proxy at `/api/proxy`. Never put a token in `localStorage`, a
    non-httpOnly cookie, or a props tree — see
    [ADR 0008](docs/adr/0008-bff-token-cookies.md).

## UI conventions

The design system is [shadcn/ui](https://ui.shadcn.com) (new-york style) on
Tailwind v4, vendored into `src/shared/ui/` and configured by `components.json`.
Consistency is the point: two components that look alike but were built
differently is the failure mode this section exists to prevent.

### Components

1. **Compose, don't create.** Before writing any markup, check whether shadcn
   ships the primitive — `Button`, `Input`, `Card`, `Dialog`, `Sheet`,
   `DropdownMenu`, `Select`, `Tabs`, `Tooltip`, `Table`, `Badge`, `Alert`,
   `Skeleton`, `Separator`, `Avatar`, `Popover`, `ScrollArea`, `Switch`,
   `Checkbox`, `Textarea`, `Label`. A bespoke `<button className="…">` in a
   feature is a bug, not a shortcut.
2. **Add new primitives with the CLI**, never by hand:

   ```bash
   pnpm dlx shadcn@latest add <component>   # writes src/shared/ui/<component>.tsx
   ```

   Then re-export it from `src/shared/ui/index.ts`. Nothing else changes.

3. **Import from `@/shared/ui`**, never `@/shared/ui/button`, and never from
   `radix-ui` in a feature — a feature that reaches for a Radix primitive
   directly is a missing shadcn component.
4. **The barrel is the bundle.** `src/shared/ui/index.ts` exports _adopted_
   components only — every client component named there lands in the shared
   client chunk on every route, because Turbopack cannot tree-shake across a
   `'use client'` re-export. The rest of the folder is vendored and ready but
   unexported (and so ignored by `knip`). Using one for the first time means
   adding its export line; removing its last call site means deleting it again.
   Exporting all 23 of them costs ~40 kB gzipped on every page — measured, and
   enough to blow the `size-limit` budget on its own.
5. **Don't restyle a primitive at the call site.** `className` is for layout
   (spacing, grid placement, width), not for colour, radius or typography. If a
   button needs a new look, add a `variant` in `button.tsx` so every call site
   gets it.
6. **Local deviations from upstream are commented as such.** There are three,
   each marked `Local deviation from upstream shadcn` so `shadcn add --overwrite`
   does not silently drop them:
   - `button.tsx` — `type` defaults to `"button"`.
   - `form.tsx` — `FormMessage` carries `role="alert"`; the statically-dead
     `useFormField` guard is removed (it fails `no-unnecessary-condition`).
   - `sonner.tsx` — theme comes from our Zustand store, not `next-themes`.

   After re-generating a component, re-read it: upstream code does not pass this
   repo's lint gate unmodified.

7. **Forms use the `Form` primitives** (`FormField` / `FormItem` / `FormLabel` /
   `FormControl` / `FormDescription` / `FormMessage`) over react-hook-form. They
   own the `htmlFor` / `aria-describedby` / `aria-invalid` wiring — never
   hand-write it. `create-user-form.tsx` is the reference.
8. **Toasts come from `Toaster` in `@/shared/ui`**, mounted once in
   `AppProviders`. Import `toast` from `sonner` to fire one.
9. **Provider-backed primitives are mounted once in `AppProviders`** and
   mirrored in `renderWithProviders`, or they throw at runtime. `Tooltip` is the
   one to watch: adopting it means adding `TooltipProvider` in both places.

### Theming — both modes, always

Dark mode is class-based (`.dark` on `<html>`), applied before first paint by
`THEME_INIT_SCRIPT` and owned by `useThemeStore` (`light` / `dark` / `system`).

1. **Every colour is a token from `globals.css`.** The token set is shadcn's
   vocabulary — `background`, `foreground`, `card`, `popover`, `primary`,
   `secondary`, `muted`, `accent`, `destructive`, `border`, `input`, `ring`,
   `chart-1…5`, `sidebar-*` — plus project-local `success` and `warning`. Use
   the paired foreground (`bg-primary text-primary-foreground`); never pair a
   token with a hard-coded text colour.
2. **A new token is defined in `:root` _and_ `.dark`.** Both, in the same commit,
   or the theme is broken in one mode and nobody notices until a user does.
3. **`dark:` at a call site is a smell.** It means the token is wrong. Reach for
   it only for genuinely mode-specific treatments (a shadow, an image opacity) —
   never to fix a colour.
4. **Check both modes before claiming done.** The theme toggle is on every page
   during development; flip it.

### Design bar

1. **Spacing is the 4px scale** — Tailwind's `gap-2`/`p-4`/`space-y-6`. No
   arbitrary values (`p-[13px]`) without a comment saying why.
2. **Radius comes from `--radius`** via `rounded-sm|md|lg|xl`. No `rounded-[7px]`.
3. **Depth is `border` first, `shadow-xs`/`shadow-sm` second.** Heavy shadows read
   as a different app in dark mode.
4. **Every interactive element has hover, focus-visible, disabled and (where it
   applies) loading states.** shadcn's variants give you the first three free —
   deleting them is a regression.
5. **Icons are `lucide-react`**, sized by the primitive (`[&_svg]:size-4`), and
   `aria-hidden` when a text label is already present.
6. **Respect `prefers-reduced-motion`** — handled globally in `globals.css`; do
   not re-introduce motion with inline styles that bypass it.
7. **Layout is responsive and content-driven**: `max-w-*` + `text-balance` /
   `text-pretty` for prose, flex/grid for structure, no fixed pixel widths.
8. **Accessibility is not a follow-up.** Roles and names first, visuals second —
   `jsx-a11y`'s strict ruleset is on and tests query by role and label.

## Adding a feature

1. Where does it belong? A user _action_ → `features/`. A domain _thing_ →
   `entities/`. A composite block → `widgets/`. Page layout → `views/`.
2. Scaffold it — don't hand-create the directories:

   ```bash
   pnpm gen:slice features/create-course --segments ui,model,api
   ```

3. Export the public surface from `index.ts` and nothing else.
4. Forms: derive the Zod schema from `apiSchemas.*` rather than restating rules.
5. Data: use `userQueries.*`-style wrappers over generated query options; never
   hand-write a query key.
6. Needs the signed-in user? `getCurrentUser()` from `@/shared/auth` on the
   server, `useSession()` from `@/entities/session` in a client component.
7. Build the UI from `@/shared/ui` only — see [UI conventions](#ui-conventions).
8. Write the test alongside the code. Query by role and label.

## Before claiming done

```bash
pnpm verify     # lint + format + typecheck + arch + cycles + deadcode
                # + i18n parity + coverage + build + size budgets
```

`verify` runs exactly what CI runs — if it passes locally it passes on the PR.
Keep it that way when you add a check to either side.

Do not silence a rule to make this pass. If a rule is genuinely wrong, change the
config and say why in the commit.
